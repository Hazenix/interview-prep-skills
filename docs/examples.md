# 使用示例

以下示例使用虚构的项目和简历条目。模拟面试片段从配置完成后开始，实际追问会随回答变化。

## 简历条目打磨

```text
用 resume-bullets 打磨我的个人项目经历。导入任务从逐行写入改为分批提交。同一份一万行文件在同一环境下导入，旧版用时 120 秒，新版用时 35 秒。
```

候选条目摘录

> 将任务导入从逐行写入改为**分批提交**，使用同一份一万行文件在同一环境下复测，**导入耗时从 120 秒降至 35 秒**。

完整文档会列出候选条目和推荐条目，并记录测试条件、基线及结果。估算值会标明待验证，并附验证方法。

## 前端模拟面试

```text
用 frontend-interview-simulator 开始一场前端校招模拟面试。
简历条目：负责商品列表页的搜索交互，修复了快速输入时结果跳回旧关键词的问题。
```

> **面试官**：快速输入时，旧关键词的结果是在什么情况下覆盖新结果的？
>
> **候选人**：我连续发了两个请求，第一个请求返回得更晚，却最后更新了页面。
>
> **面试官**：你怎么判断某次返回结果仍属于当前输入的关键词？

反馈示例：你识别了请求返回顺序与页面状态之间的竞态。下一步练习用请求序号或取消机制实现修复，并设计一次乱序返回的测试。

## 后端模拟面试

```text
用 backend-interview-simulator 开始 Java 后端校招模拟面试，重点深挖我的项目。
简历条目：给商品详情服务加了 Redis 缓存，减少高峰期数据库读请求。
```

> **面试官**：哪些商品数据会进入缓存？为什么？
>
> **候选人**：我缓存了商品详情。这个接口读多写少，同一个热门商品会被反复查询。
>
> **面试官**：商家更新商品详情后，你怎么让读请求尽快看到新数据？
>
> **候选人**：更新数据库后删缓存，下一次读请求再回填。
>
> **面试官**：如果一个读请求在更新前查到了旧值，却在删缓存之后才回填，会发生什么？

反馈示例：你讲清楚了为什么选择缓存，也说明了更新顺序。下一步练习用时间线解释旧值回填的条件，再说明你会怎么验证这个问题。

## AI 应用开发模拟面试

```text
用 ai-dev-interview-simulator 开始一场 AI 应用开发模拟面试，重点练 RAG 评估。
简历条目：为内部知识问答工具加入混合检索和重排，改善了政策条款的召回。
```

> **面试官**：你用什么证据判断政策条款的召回有改善？
>
> **候选人**：我用了一组人工标注的查询，对比改动前后的 Recall@5。
>
> **面试官**：这次同时改了混合检索和重排。你会怎么区分两项改动各自的效果？

反馈示例：你给出了可以复测的指标。下一步准备一组对照实验，并举一个检索到了相关条款但回答仍然错误的例子。

## 简历批量出题

```text
用 resume-interview-question-generator 根据下面的简历条目生成题单，只要问题。
简历条目：负责订单异步处理链路，用消息队列削峰并优化失败重试。
```

Markdown 题单摘录：

```markdown
# 项目经历 · 订单异步处理链路

## 1. 引入消息队列后，订单从接收到处理完成经过哪些环节？

### 高峰期间，你怎么判断队列是在吸收短时流量，还是出现了持续积压？

## 2. 原来的失败重试遇到了什么问题，你改了什么？

### 哪些错误适合重试，哪些错误应该直接停止？

### 如果重试导致同一订单被消费两次，你怎么避免重复处理？
```

完整题单默认保存到调用时工作目录的 `./resume/`。想一起准备回答，可以在同一条请求中写明“附简短参考回答”，并提供相关代码、项目文档或补充说明。
