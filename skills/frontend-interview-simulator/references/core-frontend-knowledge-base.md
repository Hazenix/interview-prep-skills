# 通用前端知识库

本文件是考察点与判断依据，不是逐题照念的清单。优先从候选人的项目或 JD 选场景；每次只问一个问题。`core:*`、`js:*`、`ts:*`、`engineering:*` 为建议的主题 ID 前缀。浏览器、框架和工具的具体实现可能随版本变化，先确认环境再评价。

## HTML、CSS 与可访问性

| 场景或主问题 | 可靠回答应涉及 | 适合继续追问的一点 |
|---|---|---|
| 页面由大量 `div` 组成，键盘用户无法操作菜单，如何改？ | 语义元素、原生交互控件、焦点顺序、可见焦点、键盘操作与验证 | 菜单关闭后焦点应该回到哪里？ |
| 一个卡片列表在手机上溢出，如何定位和修复？ | viewport、盒模型、最小宽度、长内容、响应式约束与真机检查 | 很长且不可换行的内容怎么处理？ |
| `position: sticky` 没有生效，先查什么？ | 滚动容器、包含块、偏移值、祖先 overflow 与可用空间 | 哪个元素实际在滚动？ |
| 同样的组件在某页面层级错乱，怎样解释？ | stacking context、定位、`z-index` 生效条件、transform/opacity 等影响 | 如何通过 DevTools 找到真正的层叠上下文？ |
| 图片和图标如何写替代文本？ | 信息性图片描述含义；装饰性图片避免重复朗读；图标按钮要有可访问名称 | 只显示放大镜图标的搜索按钮怎么命名？ |
| 表单只靠颜色显示错误会怎样？ | label、错误文本与控件关联、焦点/状态提示、对比度、键盘与读屏验证 | 提交失败后用户怎样知道第一个错误在哪？ |

不要把“用了 ARIA”视为充分答案。优先评价语义与可操作行为，再看 ARIA 是否补足必要信息；视觉截图不能证明键盘或读屏可用。

## JavaScript 与 TypeScript

| 场景或主问题 | 可靠回答应涉及 | 适合继续追问的一点 |
|---|---|---|
| 搜索框连续输入时旧请求覆盖新结果，怎么处理？ | 请求序号或取消、结果归属、错误状态、竞态复现 | 取消请求是否等于服务端从未收到请求？ |
| 页面有长任务导致点击迟迟无反馈，怎么定位？ | 主线程任务、Performance 录制、拆分任务或转移计算、交互指标 | 如何证明改动改善了真实用户交互？ |
| `Promise`、`queueMicrotask` 与 `setTimeout` 的输出顺序如何推导？ | 同步代码、任务与微任务队列、当前环境；不能靠背固定输出 | 如果微任务不断追加微任务，会怎样影响渲染？ |
| 闭包导致组件卸载后仍保留大对象，怎样排查？ | 引用链、监听器/定时器/订阅清理、heap snapshot、复现条件 | 修复后如何证明对象能被回收？ |
| `this` 在回调中为何变化？ | 调用方式、箭头函数词法绑定、显式绑定及事件回调约定 | 换成箭头函数是否改变 `arguments` 和构造行为？ |
| 一个共享对象被浅拷贝后出现意外联动，怎样解释？ | 顶层复制、嵌套引用共享、所需的不变式与具体复制策略 | 哪些数据不能简单用 JSON 序列化复制？ |
| API 返回联合类型，如何让分支更安全？ | discriminated union、类型收窄、穷尽检查、运行时数据校验 | TypeScript 类型能否保证网络响应真的符合接口？ |
| 泛型工具函数被大量 `any` 绕过，怎么收紧？ | 输入输出关系、`unknown` 与边界校验、类型约束、避免不必要断言 | 什么时候应保留运行时验证？ |

对事件循环题要限定浏览器或 Node.js 环境；不要把所有异步回调压成“宏任务/微任务”口诀。对 TypeScript 只评价静态检查提供的保证，不能声称它会自动验证运行时 JSON。

## 浏览器、网络与安全

| 场景或主问题 | 可靠回答应涉及 | 适合继续追问的一点 |
|---|---|---|
| 部署新版本后部分用户仍看到旧 JS，怎么排查？ | HTML 与静态资源缓存策略、带内容哈希文件名、CDN/Service Worker、网络面板验证 | 为什么只给 JS 文件加 `no-cache` 可能不够？ |
| 点击链接后页面为何变白屏？ | 路由、资源加载、运行时异常、API、部署版本不一致及监控线索 | 如何区分资源 404 和 JS 异常？ |
| 一个跨域请求失败，怎样定位？ | 同源策略、CORS 预检条件、响应头、凭据策略、Network 证据 | 预检通过但实际请求仍失败，下一步查什么？ |
| 页面把用户提供的富文本直接插入 DOM，有什么风险？ | XSS、按上下文转义或可信清洗、避免危险 API、CSP 为纵深防御 | 为什么只做输入过滤不够？ |
| 请求带 Cookie 时如何考虑 CSRF？ | Cookie 发送条件、SameSite、服务端 CSRF 防护、跨站与跨源区别 | `SameSite` 是否覆盖所有业务场景？ |
| 一个脚本包突然变大且来自第三方，怎样评估？ | 依赖来源、版本锁定、权限与隐私、构建体积、加载失败影响 | 如何限制第三方脚本可访问的数据？ |

安全题只讨论防护与验证，不要求候选人复现攻击。HTTP 缓存题要区分浏览器缓存、CDN 和 Service Worker；不能把“强缓存”“协商缓存”当作所有实现的完整解释。

## 性能、工程化与排障

| 场景或主问题 | 可靠回答应涉及 | 适合继续追问的一点 |
|---|---|---|
| 简历写“首屏快 40%”，怎么验证？ | 指标定义、基线、设备/网络条件、实验与真实用户数据、样本量、回归监测 | 用户感到卡时，LCP 变好是否已足够？ |
| 图片造成明显布局跳动，怎么改？ | 预留尺寸、容器稳定性、字体/异步内容、CLS 的定位与复测 | 延迟加载图片时还要保留什么？ |
| 交互卡顿但网络请求很快，先看什么？ | 主线程长任务、渲染/布局/绘制、组件更新、设备档位、Performance 证据 | 怎样区分脚本计算和样式布局的开销？ |
| 包体积突然增加，如何找到来源？ | 构建分析、依赖变化、动态导入、tree shaking 前提、缓存与发布验证 | 为什么“代码分割”不必然减少总字节数？ |
| 发布后线上白屏，如何止损并定位？ | 影响范围、回滚或降级、错误监控、source map、资源版本、复现与验证 | 缺少 source map 时还能拿到什么线索？ |
| 组件库升级导致多项目样式冲突，怎么治理？ | API/样式契约、版本管理、视觉回归、迁移计划、灰度与回退 | 如何证明只影响特定组件？ |
| 用户报告错误但本地无法复现，如何收集证据？ | 浏览器与版本、设备/网络、步骤、日志、监控、隐私边界 | 如何避免把真实用户数据直接写进演示或日志？ |

性能判断先说“测什么、怎么测、样本是什么”，再谈优化。LCP、INP、CLS 是不同体验维度；实验室测试与真实用户数据也不能互相替代。对构建工具、SSR 或框架内部机制先问版本与部署模式。

## 场景追问示例

项目写“优化了首页”时，先问：“你负责的改动是什么，优化前用什么指标衡量？”若回答“把图片改成懒加载”，下一轮可问：“首屏主图也懒加载后，LCP 可能发生什么变化？”再根据回答追问验证方法。不要在首轮把这些问题全部抛出。
