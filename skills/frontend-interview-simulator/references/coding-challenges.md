# 前端编码题

仅在候选人选择编码环节并确认 JavaScript/TypeScript 后读取。每次只选一道合适题目；给完整题面、输入输出和约束，本轮只要求交代码。评审时按“正确性 → 边界 → 复杂度 → 可读性/验证”逐轮追问，不一次抛出全部问题。可根据项目场景改写题目，但不能为了迎合答案改动原题协议。没有实际运行就标明“根据代码推断”。

## A. 防抖搜索回调（实习）

实现 `debounce(callback, delay)`，返回一个函数。连续调用返回函数时，只在最后一次调用后的 `delay` 毫秒执行一次 `callback`；使用最后一次调用的参数和调用时的 `this`。`delay` 为非负整数；无需实现 `leading`、`cancel`、`flush`。

```text
时间 0 ms: fn("a")
时间 30 ms: fn("ab")
时间 80 ms: fn("abc")
delay = 100 ms
预期：约 180 ms 时只调用 callback("abc") 一次
```

评估：计时器替换、参数与 `this`、0 延迟、卸载或销毁时可能需要取消的工程边界。不要把定时器精度当成毫秒级保证。

## B. 扁平目录转树（实习/校招）

实现 `buildTree(items)`。每项为 `{id, parentId, name}`，`parentId=null` 表示根节点。输入 ID 唯一、无环、每个非根节点的父节点都存在，但父节点可能在数组中后出现。输出根节点数组；每个节点保留原字段，并新增 `children` 数组；同级顺序保持输入顺序。不要修改输入对象。

```text
输入：[{id: 2, parentId: 1, name: "B"}, {id: 1, parentId: null, name: "A"}]
输出：[{id: 1, parentId: null, name: "A", children: [{id: 2, parentId: 1, name: "B", children: []}]}]
```

评估：乱序父节点、多个根、空数组、时间/空间复杂度和输入不变性。若候选人自行加入缺失父节点或环检测，先确认这是扩展需求，不能反过来扣原协议分。

## C. 有并发上限的异步映射（校招/社招）

实现 `mapLimit(items, limit, worker)`，`items` 是数组，`limit` 是正整数，`worker(item, index)` 返回 Promise。最多同时运行 `limit` 个 worker；成功时返回按输入顺序排列的结果数组。任一 worker 失败时，返回的 Promise 拒绝且不再启动未开始的任务；已经启动的任务允许继续完成，不要求取消。空数组返回 `[]`。

```text
items = [3, 1, 2], limit = 2
worker 对每项等待 item × 10 ms 后返回 item × 2
预期结果：[6, 2, 4]；任一时刻运行中的 worker 不超过 2 个
```

评估：并发上限、结果顺序、拒绝后停止派发、空数组、`limit > items.length`、原始错误传播。不要仅看最终数组，还要追问如何测量同时运行的数量。

## D. 前端故障代码阅读（按项目改写）

给出一个简短、可自洽的组件或浏览器代码片段，其中包含一种可观察错误：例如旧请求覆盖新搜索结果、列表使用不稳定 key、卸载后订阅未清理。先只问“指出最可能导致该现象的代码路径并给修复”。下一轮再问复现与测试。出题时写明框架、版本、输入顺序和预期行为；没有相应框架范围时使用原生 JavaScript 片段。
