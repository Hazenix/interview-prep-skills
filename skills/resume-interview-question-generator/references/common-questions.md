# 常见面试问题

按经历类型选用问题，并根据简历中的公司、项目和工作内容调整称呼。

## 整段实习或项目：介绍类问题

- 请做个自我介绍，重点说与应聘岗位相关的经历和你亲自完成的工作。
- 介绍一下你在 XXX 的实习吧。
  - 回答架构：大部门业务 → 我们的服务在其中的作用 → 一个具体例子 → 我负责的工作。
- 你们部门是做什么的？（适用于实习）
- 你们项目组的人员配置和分工是怎样的？（适用于团队项目或实习）
- 平时的开发流程和节奏是怎样的？（适用于实习）
- 介绍一下你们的平台/你们组的业务。
  - 追问：QPS、PV、UV 分别是多少？口径和高峰时段是什么？
- 你们系统或平台的整体架构是怎样的？能简单讲讲吗？
- 如果有几段经历，你会选哪一项重点介绍？为什么它最能代表你的能力？
- 这个项目/平台是要解决什么问题？目标用户是谁？
- 这个项目实际运行到什么程度了：本地演示、测试环境还是线上使用？你负责的部分覆盖到哪里？
  - 追问：哪些部分是你独立完成的，哪些依赖同事或其他团队？

## 整段实习或项目：亮点、难点与故障

- 你觉得这段实习里最有亮点的工作是什么？/你觉得项目中最大的亮点是什么
- 你觉得实习/项目中最难、最有挑战的事情是什么？你是怎样解决的？
  - 回答架构：需求背景 → 工作链路 → 真正的难点 → 考虑过的方案 → 最终选择及理由。
- 遇到过线上故障吗？你是怎么定位、处理和解决的？
- 现在回头看，这个项目还有什么不足？如果继续做，你会先改进哪里？

## 针对具体的一条简历内容

- 你简历上写了 XXX，能简单讲讲是怎么做的吗？
  - (追问：你是怎么定位到这个性能瓶颈或故障原因的？有哪些日志、指标或实验支持判断？)
  - 追问：为什么选择这么做？当时还考虑过什么方案？
  - 追问：这项工作带来了什么收益？你是怎么评估/验证(优化的)效果的？
  - 追问：改动前的问题有多严重？基线、样本和指标口径是什么？
  - 追问：如果让你继续改进，你会怎么改进？
- 你提到的 XXX 在系统里具体用在哪里？输入、输出和上下游分别是什么？
- 为什么需要这项技术或这层复杂度？更简单的方案为什么不够？
- 你选择的方案与另一个常见方案相比，分别在什么场景下更合适？
- 如果流量、数据量或并发量扩大很多倍，现有方案会先在哪里遇到瓶颈？你会怎么调整？
- 如果关键依赖超时、宕机、返回错误或出现重复请求，系统会怎样表现？你会如何定位、降级和恢复？
- 这项能力如何测试或验收？上线后看哪些指标，出现回退时怎么办？

## 专业技能及简历关键词

- 你简历里写了 XXX，先说说它解决什么问题，以及你实际在哪个场景使用过。
  - 追问：它的核心机制是什么？哪些前提或边界容易被忽略？
  - 追问：和相近的技术或方案相比，你为什么选它？
- 如果改变数据规模、并发条件或故障条件，你刚才的结论还成立吗？
- 对简历写到的技术，能举一个实际使用或排障案例，而不只解释概念吗？

## 个人成长

- 实习期间你学到了什么？（适用于实习）
- 这段实习你最大的收获是什么？（适用于实习）
- 你平时怎样学习新技术？最近一次把学到的技术用到实际项目中是什么情况？

## 软技能类问题

- 你和同事合作时发生过沟通不顺或让你不舒服的事吗？你怎么处理的？（适用于团队经历）
- 你和同事对设计方案有分歧时，一般怎么处理？能举个实际例子吗？（适用于团队经历）
- 当工作依赖其他团队或同事时，你怎么同步进度、推动协作和提前暴露风险？（适用于团队经历）
